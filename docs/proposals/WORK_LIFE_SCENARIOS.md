# 使用场景调研：工作场合与生活场合的应用接入

> 项目：pokemon-remember-you（就记得是你）
> 定位：**使用指南层，非工具语义**。本文沿「工作场合 / 生活场合」这条**场景轴**调研 dex 的使用场景：各场合下对接哪些类型的应用、贡献什么记忆、以什么形态接入、优先级如何。**场景轴 ≠ 分域方案**——「工作 / 生活」是调研维度，不是推荐的一级分域；分域粒度是独立的用户治理决策（§6），工具不内置任何分域本体（P3：目录即 scope、不做本体论 / FR-3.7）。
> 文档版本：v1.2 · 2026-09-24 · 状态：待评审（v1.2：场景轴与分域解耦——接入地图升为主体、按「场合 × 应用」组织、落点语义化；分域降为独立决策章节（§6）；节奏分档改按 scope 记忆节奏、不再按场合二分；此前 v1.1：评审修订——[clients] 统一注册示例、授权边界诚实化（scope 约束协议通道不约束磁盘）、慢记忆 keep-until 建议）

## 1. 场景轴与分域：两个不同的问题

|  | 场景轴（本文的组织维度） | 分域（库的一级 scope 结构） |
|---|---|---|
| 回答的问题 | 在哪个场合用、对接哪些应用、以什么形态接入 | 结论落在哪个 scope、谁能看到 |
| work/life 在其中的角色 | 调研维度——恰好对应隐私边界（公司机 vs 个人机）、应用生态、消费方类型，粒度合适 | 多种合法分法中最粗的一种，**不是推荐**（粒度讨论见 §6） |
| 谁决定、怎么变 | 随接入生态自然扩展 | 用户治理决策；变更走 scope 改名协议（设计 §5.6） |

两点澄清（防常见误读）：

- **work/life 作为轴合适、作为分域偏粗**：二分把技术栈、团队、会议结论、客户、职业偏好全塞进一个 work 域；一级域软预算允许到 8 个（FR-2.9），内容量大的用户自然长出按客户/雇主/主题的细分（拆细判据见 §6）。
- **访问控制的载体是客户端授权边界，不是目录二分**：「哪些消费方看哪部分记忆」由每个 client 的 scope 集合表达（FR-10.3 默认全拒）——任何分域粒度下都能表达「工作侧消费方看这几个 scope、生活侧看那几个」，不需要库结构恰好长成两块。

## 2. 接入判据与形态

> 三判据：**结论密度**（单位数据里「活过三个月的关于我的结论」占比）／**过程可留源侧**／**噪音隐私比**。
> 形态三种：**收割**（一次性批量蒸馏）、**digest**（周期模式蒸馏）、**常驻**（双向集成）。优先级：★★★ 高 / ★★ 中 / ★ 低 / ☆ 谨慎。
> 只推荐常驻的是每天用的（编码 agent、IM bot、待办），其余来源冷启动价值大于持续同步价值——避免把 Spoke 生态做成集成地狱。

「落点」列用**语义**描述：结构层锚点 `person/`、`projects/`、`apps/` 是目录白名单固定的；「工作侧域 / 生活侧域 / 人物页」指你的分法中承载该类结论的 scope——叫什么名字、拆多细由 §6 决定，本文不预设。

## 5. 跨场合通用与反推荐

### 跨场合通用

| 来源 | 贡献 | 落点（语义） | 形态 | 优先级 |
|---|---|---|---|---|
| 存量笔记（Obsidian / Apple Notes） | 冷启动第一矿 | 按 §7 决策树分流至各 scope | 一次性收割 | ★★★ |
| 全局工具配置（`~/.claude/AGENTS.md`、`~/.pi/agent/AGENTS.md`、`~/.zcode/AGENTS.md`） | 已成型的个人原则与偏好 | 跨场景成立 → `person/`；工作相关 → 工作侧域 | 一次性收割 | ★★★ |
| 个人写作（博客、周记、日记） | 写作即记忆——最真实的自我表达 | 按内容分流 | 收割 + 手动增量 | ★★★ |
| 浏览器（书签、剪藏、save-later） | 反复保存的规律（不收链接本身） | 按内容定 | digest | ★ |

### 反推荐（写明防漂移——「大一统诱惑」在来源维度的防线）

- **凭证/密码类**：任何形态不入库（NFR-1 + 密钥守卫）；
- **财务明细、位置轨迹**：风险收益不成比例，至多「我订阅了 X」级结论；
- **原始日志全量**（浏览历史、shell history、邮件原文）：违反「过程留源侧」；
- **公司机密与源码细节**：repo 自己是事实源；
- **他人原话**：任何来源（IM/会议）只蒸馏第一人称结论，人物页只存「我与某人的关系」。

## 6. 分域粒度：独立的用户决策

接入地图回答「接什么、落在哪类结论」；本节回答「那类结论的 scope 在库里长什么样」——粒度与场合正交，以下均为合法分法，工具侧零改动。

**分域解决什么**（动机成立，但粒度开放）：

| 动机 | 说明 |
|---|---|
| 授权组合的便利 | 按域组合 scope 最直观：公司机 agent 不挂生活记忆、家里 bot 不挂项目细节——载体仍是 client 的 scope 集合（§1），分域只是让集合好写 |
| person/ 恒注入的谨慎判据 | `person/` 全消费方默认可见（FR-3.1）⇒ 只宜放通用自我事实，场景特定内容需有处下放——分域提供下放位置 |
| 记忆节奏的配档 | 衰减分档（FR-6.5）与回顾分组（FR-9.5）以一级 scope 为键，分域清晰则快慢档好配 |

**三种粒度（示例）**：

```text
A. 不分域          全放 person/ + 主题文件；记忆量小时最省心
B. work/life 二分   最常见起点（目录示例如下），后续按拆细判据演化
C. 按客户/主题细分  自由职业者 domains/client-a|client-b|personal；或 domains/engineering|management
```

```text
# 分法 B 目录示例
person/              ← 恒注入层：愿意让全部消费方看到的通用自我事实
domains/work/        ← 工作结论：技术栈、团队、会议结论、职业偏好
domains/life/        ← 生活结论：健康、家庭、爱好（先内容后结构，不预建）
domains/people/      ← 人物页：第一人称，只存「我与某人的关系」
apps/ projects/      ← 结构层固定：projects 多偏工作侧；apps 按应用定
```

**拆细判据**（什么时候该把一个域裂开）：

- 达到新域准入阈值：同类条目 ≥10 且连续两周进入回顾清单（FR-2.9「先内容后结构」）；
- 授权需要分化：某部分内容需要单独授予/隔离某类消费方，现有 scope 粒度已不够表达（如自由职业者按客户隔离授权）；
- 节奏需要分化：域内一半快一半慢，per-scope 衰减分档（FR-6.5）配不平。

分法变更走 scope 改名协议（设计 §5.6）：`git mv` + 同步 config/render/MCP 白名单/@import 引用。

## 7. 内容分流决策树与 person/ 收紧判据

```text
① 愿意让所有消费方看到吗？—— 是 → person/（恒注入层，只放通用自我事实）
                                否 → 承载它的分域 scope（名字由 §6 分法定）
② 关于我，还是关于项目/应用？—— person vs projects/apps（需求 §3.7）
③ 换一个应用还成立吗？—— 不成立则留 Spoke（需求 §3.2）
```

场合示例对照（树本身与场合无关）：「我周末爬山」→ ①否 → 生活侧 scope（分法 B 下为 `domains/life/`）；「提交前必跑 lint」→ ①是 ②跨项目成立 → `person/`；「我对某同事的看法」→ ①否，且绝不能进任何工作消费方可见层。

**person/ 收紧判据**：只放愿意让**全部**消费方看到的通用自我事实——身份与角色、通用偏好（写作/沟通风格）、硬性禁区、跨场景成立的习惯。判断口径：「这条事实让任何一个接入的 agent 知道都无害且有用吗？」

## 8. 消费方授权组合与最小授权（示例）

示例 scope 名取自 §6 分法 B；换任何分法，组合逻辑不变。

```toml
[clients."work-laptop-zcode"]        # 工作场合：公司机编码 agent（统一客户端注册，FR-10.1）
scopes = ["person", "domains/work", "projects/current"]
render = { out = "AGENTS.md" }       # 默认 repo 根（个人仓库）；团队仓库走 @import/rules 分流（TOOL_COMPATIBILITY.md）

[clients."tg-bot"]                   # 生活场合：IM bot
scopes = ["person", "domains/life", "apps/todo"]
propose = true

[clients."cloud-writer"]             # 远程/第三方（US-08）：经网关持凭证，最小授权子集
scopes = ["person", "domains/work"]
propose = false
```

**最小授权原则**（语义中立，覆盖一切分法）：按消费方实际需要授予 scope 子集，默认全拒（FR-10.3）。公司环境的托管 agent「不挂个人库全量」是该原则的实例而非场景特例——多机同步（US-07）之外最易被忽视的暴露面。注意边界：scope 白名单约束的是 CLI/MCP 协议通道，**不改变磁盘内容**——公司机只要 clone 了仓库，未授权的域文件就在磁盘上（分法 B 下即生活域）；「公司机不持有生活记忆」须靠 clone 内容解决（独立远端/裁剪分支），属仓库内容问题而非授权配置问题（设计 §10 威胁模型）。

## 9. 节奏与参数建议（按 scope 记忆节奏分档）

分档依据是 **scope 自身的记忆节奏**——该 scope 的结论多久失真——而非它属于工作还是生活场合：工作场合也有慢记忆（职业身份事实、长期合作者的关系），生活场合也有快记忆（旅行计划、进行中的事务）。

- **衰减分档**（per-scope 覆盖，FR-6.5 / 设计 §5.4）：快节奏 scope（项目层、进行中的客户）缺省 90 天；慢节奏 scope（人物页、健康模式、身份事实）可放宽至 180 天——数值是示例，按 scope 实际节奏在实现时定；慢记忆暂不归档时用 keep-until 到期注释「谢绝提醒」（FR-2.10），到期强制复审；
- **回顾分组**：`dex review` 按一级域分组（FR-9.5），组序可配、支持只清单组——「先工作侧后生活侧、工作日碎片时间只清工作侧」是分法 B 下的分组策略示例，分组键始终是一级 scope 而非场合；
- **升降级高频来源**：coding 场景（`projects/foo/` → 工作侧域，或跨场景成立则 `person/`），周回顾重点关照。

## 10. 待定数值

90/180 天衰减窗口（快/慢节奏 scope 的两个示例档）、domains 一级软预算 ≤8（FR-2.9，通用约束非特定分法特有）、新域准入阈值（≥10 条 × 连续两周进回顾清单，FR-2.9）——均在实现阶段经真实使用校准。
